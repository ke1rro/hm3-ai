## 1. Постановка задачі

Потрібно побудувати NLP-класифікатор, що визначає походження тексту, відносячи його до **одного з трьох класів**:

| Label | Значення |
|---|---|
| `human` | Текст написаний людиною. |
| `ai` | Текст згенерований LLM. |
| `fusion` | Змішане авторство: людський текст частково переписаний LLM. |

Це **supervised multiclass text classification** для текстів англійською та німецькою мовами. Дані охоплюють новини, наукові статті, блоги, парламентські дебати, судові документи, студентські есе та книжки.

**Очікуваний результат:** для **кожного** запису `test.csv` передбачити одну з міток `human`, `ai`, `fusion` і сформувати коректний файл submission.

## 3. Метрика та оцінювання на Kaggle

Основна метрика — **macro-averaged F1** для трьох класів:

\[
F1_{\mathrm{macro}} = \frac{F1_{\mathrm{human}} + F1_{\mathrm{ai}} + F1_{\mathrm{fusion}}}{3}.
\]

Де для кожного класу:

\[
F1 = \frac{2\,\mathrm{Precision}\,\mathrm{Recall}}{\mathrm{Precision}+\mathrm{Recall}}.
\]

Кожен клас має **однакову вагу** незалежно від його частоти. Вищий score — кращий результат.

Використовувати таку саму метрику локально:

```python
from sklearn.metrics import f1_score

score = f1_score(y_true, y_pred, average="macro")
```

Розподіл leaderboard:

| Частина | Розмір | Призначення |
|---|---:|---|
| Public leaderboard | **7 501** (≈30% test) | Проміжний результат на Kaggle. |
| Private leaderboard | **17 499** (≈70% test) | Фінальний рейтинг. |

Розподіл конкретних test ID між public/private **не розкривається**. Private leaderboard впливає на **2 з 10** основних балів домашнього завдання.

## 4. Формат submission

Файл повинен мати **рівно дві колонки**:

```csv
id,label
8ff2d1,ai
a261cf,ai
ad5614,ai
```

Це **приклад формату**, а не справжні labels тестових рядків.

Обов'язкові умови:

1. У файлі мають бути всі **25 000** test ID, кожен **рівно один раз**.
2. Значення `label` — лише **нижнім регістром**: `human`, `ai`, `fusion`.
3. **Порядок рядків** має відповідати `sample_submission.csv`.
4. Після сортування, shuffle або batch inference передбачення треба **вирівняти за `id`**.
5. Не записувати DataFrame index або додаткові колонки.
6. Ліміт — **5 submissions на день**.
7. До дедлайну можна вибрати **до 2 фінальних submissions**.

## 7. Правила та обмеження

### Моделі та джерела даних

- **Заборонено:** proprietary/closed LLM через API чи chat-інтерфейс (зокрема GPT, Claude, Gemini) **для labeling, generation або feature extraction із даних**.
- **Дозволено:** open-weight models, зокрема XLM-R, mDeBERTa, Llama, Qwen.
- **Заборонено:** будь-які зовнішні дані чи lookup для покращення тестових передбачень, включно з публічним джерелом GhostWriter.
- **Дозволено:** pretrained model weights.
- Навчання/адаптацію для задачі потрібно виконувати **на `train.csv`**.

### Data leakage

Не можна підлаштовувати під validation/test:

- vectorizers (`fit`, `fit_transform`);
- scalers;
- feature selection;
- trainable preprocessing або інші процедури, що «вивчають» параметри з даних;
- моделі з використанням прихованих test labels у будь-якій формі.

Усі методи порівнюються на **одному fixed validation split** з Macro-F1.

### Самостійність та інструменти

- Робота індивідуальна: **поширення коду між учасниками веде до 0 балів**.
- Потрібно цитувати зовнішній код та ідеї.
- AI-інструменти **дозволені для написання коду**, але **не для написання звіту**.
- Дозволені технічні нотатки й аналіз не слід автоматично переносити в заборонений AI-written report.
- За довгі нефільтровані outputs, runtime errors і неструктурований код знімаються бали.
